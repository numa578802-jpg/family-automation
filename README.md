# family-automation

家族の予定を自動でGoogleカレンダーに集約するGoogle Apps Script(GAS)プロジェクト一式です。
`gas/` フォルダの中身を、そのままGoogle Apps Scriptエディタにコピーして使います
(clasp等でのデプロイは前提にしていません。ファイル単位でコピー&ペーストしてください)。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `家族スケジュール自動登録.gs` | 既存資産。「家族スケジュール」フォルダのPDF/写真をGemini APIで解析し、Googleカレンダーへ自動登録する。 |
| `appsscript.json` | GASのマニフェスト。タイムゾーン(Asia/Tokyo)、Webアプリの公開設定、Calendar詳細サービスの有効化を含む。 |
| `WeatherNotify_Config.gs` | 今回追加した天気×カレンダー通知機能の設定値(地点住所・しきい値・登校日判定の共通ロジック)。 |
| `WeatherNotify_Api.gs` | 気象庁 予報JSON(降水確率)・Yahoo! YOLP気象情報API(降水ナウキャスト)・ジオコーディング・自転車移動時間の取得。 |
| `WeatherNotify_YukiLogic.gs` | ゆうきさん(刈谷高校)のバス/自転車判定ロジック(朝の登校・帰りの下校、往復で判定)。 |
| `WeatherNotify_MitsukiLogic.gs` | みつきさん(前林中学校)の出発時刻リマインド、および部活動/お茶の日の送迎提案ロジック。 |
| `WeatherNotify_Line.gs` | LINE Messaging APIへのpush送信、および友だち追加後のuserId自動登録用Webhook(`doPost`)。 |
| `WeatherNotify_Main.gs` | 配信のメインエントリ(`sendProvisionalNotification` / `sendFinalNotification`)、メッセージ文面の組み立て、トリガー設定、下校時アラートの予約。 |
| `WeatherNotify_SafetyAlerts.gs` | 気象庁 警報・注意報JSONによる危険警報(レベル4相当)チェック。**判定ロジックは未検証・暫定実装**(下記参照)。 |
| `WeatherNotify_Test.gs` | 本番反映前の動作確認用テスト関数群。 |

## 配信メッセージの一覧

前日21:00頃(暫定版)・当日6:30頃(確定版)の2回、以下のメッセージが判定条件に応じて配信されます。

| メッセージ | 対象 | 配信条件 | 内容 |
|---|---|---|---|
| 登校 天気予報(バス/自転車) | ゆうきさん | 登校日 | 朝(登校)・帰り(下校)両方の天候を見て、どちらか一方でも雨天条件を満たせば往復ともバス推奨。良好なら自転車推奨。 |
| 出発時刻のお知らせ | みつきさん | 登校日または正午以降に時刻付きの予定がある日 | 朝(正午前)の時刻付き予定(無ければ登校日のとき登校(通常授業)にフォールバック)を1件目とし、正午以降に時刻付きの予定(塾・習い事等)があればそれぞれ追加の1通を配信(例: 朝の登校+夕方の英語(塾)が両方ある日は2通)。カレンダーの予定開始時刻から、自転車移動時間・雨天バッファを差し引いた出発目安時刻。ただし下校予定時刻より後に始まる**英語・お茶**の予定は、朝の時点では詳細を出さず予告のみとし、開始1時間前に別途「出発時刻のお知らせ(個別)」を配信する(下記参照)。 |
| 出発時刻のお知らせ(個別・新規) | みつきさん | 下校予定時刻より後に始まる英語・お茶の予定がある日 | 対象の予定の開始1時間前に、別トリガーで改めて配信。内容は通常の出発時刻のお知らせと同じ(予定名・家を出る目安・降水確率・出典リンク・河川水位情報リンク)。 |
| 送迎提案 | みつきさん | 部活動/お茶の予定がある日のみ | 行き・帰りの天候を見て「徒歩」「送迎(祖父母または父)」のいずれかを提案(実際の送迎手配は含まない)。 |
| 下校時 雨雲通過予報(新規) | ゆうきさん・みつきさん | 登校日(下校予定が算出できる日) | 確定版配信時に、下校予定時刻の30分前(初期値)を狙って別トリガーで配信。交通手段の提案は含まず、実測に近いナウキャストの数値のみ。 |

いずれも、判定に使った情報源(気象庁の降水確率ページ・Yahoo!雨雲レーダー)へのリンクをメッセージ末尾に付記します。
また、全メッセージの件名冒頭に対象者名(「【ゆうき】」または「【みつき】」)を付けています。

## みつきさんの習い事(英語・お茶)出発時刻の個別案内(新機能)

みつきさんの下校予定時刻(`getHomewardDepartureTime_`で算出)より後に始まる予定のうち、
家族プロフィールに登録されている習い事名(**英語・お茶**、部分一致で判定)に該当するものは、
いったん帰宅してから改めて出発することが多く、朝の時点では正確な出発時刻を出しづらいため、
朝の確定版配信では「本日は英語(塾)の予定があります(18:10〜)。出発時刻のお知らせは、
開始1時間前に改めてお送りします。」のような予告のみとし、実際の出発時刻(自転車移動時間・
降水確率を反映した目安)は、その予定の**開始1時間前**に個別の使い捨てトリガーで別途配信します
(`WeatherNotify_Main.gs`の`scheduleMitsukiLessonDepartureAlerts_`/`runScheduledMitsukiLessonDepartureAlerts_`。
下校時 雨雲通過予報と同じ、スクリプトプロパティ+使い捨てトリガーの予約方式です)。

一方、下校予定時刻より後に始まる予定でも、部活動などそれ以外(習い事名に一致しないもの)は
これまで通り扱いを変えず、朝の時点でまとめて出発時刻を案内します(学校からそのまま移動するため、
予告は不要です)。

## 危険警報チェック(新機能・警報コードの判定ロジックは未確定)

登校 天気予報(ゆうきさん)・出発時刻のお知らせ(みつきさん)の確定版配信時に、豊田市(西部2321101・
東部2321102の両区域)・知立市・刈谷市を対象にレベル4相当の危険警報(例: レベル4大雨危険警報、
レベル4土砂災害危険警報)が発表されていないか確認し、発表されていればメッセージの冒頭に明記する機能です
(`WeatherNotify_SafetyAlerts.gs`)。豊田市は自宅が西部側にあたりますが、境界付近のリスクも考慮し、
東部・西部のどちらか一方でも該当すれば警告する形にしています。対象市町村のコードは
`testDangerWarningSmoke`の実行結果で確認済みです。

> **重要**: 「危険警報」は2026年5月29日に始まったばかりの新しい防災気象情報体系です。
> `testDangerWarningSmoke`実行時点では、対象市町村のデータはcode:"20"(注意報レベル)のみで、
> 警報級以上(危険警報に相当するコード)はまだ観測できていません。そのため**判定ロジック
> (`matchesDangerWarning_`)は現状「常に該当なしを返す」暫定実装**のままです。実際に警報級以上の
> 状況が発生した際に、改めて`testDangerWarningSmoke`を実行して結果を確認し、判定ロジックを確定させる
> 方針です。それまでは、既存の通知内容には一切影響しません(安全側に倒しています)。

## 河川水位情報リンク(逢妻女川・千足橋観測所)

登校 天気予報・出発時刻のお知らせ・下校時 雨雲通過予報の全メッセージ(暫定版・確定版とも)の
**末尾**に、逢妻女川・千足橋観測所の水位情報ページへのリンクを常時付記します
(危険警報が出ている場合はそちらを本文より優先してメッセージ冒頭に表示し、河川水位情報リンクは
本文の後ろに続く形です)。

> **経緯**: 当初は国土交通省「川の防災情報」(river.go.jp)から水位・危険度を自動取得する案でしたが、
> 同サイトの「取り扱い上の注意」に「一般利用者が通常のブラウザで閲覧することを想定しており、ツールによる
> 定期的なデータ取得は控えてほしい」という趣旨の記載があったため、サイト側の要望に反する自動定期取得は
> 見送りました。代わりに、観測所の個別ページへのリンクをメッセージに載せる形にしています(自動取得なし、
> リンクのみ)。リンク先は愛知県「川の防災情報」(kasen-aichi.jp)のページで、検索で特定したものです。
> **開発環境から直接開いて内容を視覚的に確認できていないため、正しい観測所のページか一度クリックして
> ご確認ください**(`WeatherNotify_SafetyAlerts.gs`の`RIVER_LEVEL_INFO_URL_`)。

## セットアップ手順(天気×カレンダー通知機能)

### 0. 前提: 既存機能のスクリプトプロパティ

既存の `家族スケジュール自動登録.gs` 側で、すでに以下が設定済みであることを前提にしています。

- `GEMINI_API_KEY` / `FOLDER_ID` / `CALENDAR_ID`

`CALENDAR_ID`(家族の予定が登録されている共有カレンダー)を、今回の天気×カレンダー通知機能でもそのまま再利用します
(みつきさんの「【みつき】」タグ付き予定の検索、登校日判定などに使用)。

### 1. LINE公式アカウントを友だち追加してもらう(最初のステップ)

ゆうきさん・みつきさん・きくみさんに、設定済みのLINE公式アカウントをQRコード等で友だち追加してもらってください
(一志さんはこれまでの動作確認で既に友だち追加・登録済みです)。
友だち追加が完了し、後述のWebhookを設定した状態で、それぞれ本人のLINEアプリから公式アカウントのトーク画面で

- ゆうきさん → `ゆうき` と送信
- みつきさん → `みつき` と送信
- きくみさん → `きくみ` と送信

してもらうと、対応するスクリプトプロパティ(`LINE_USER_ID_YUKI` / `LINE_USER_ID_MITSUKI` / `LINE_USER_ID_KIKUMI`)に
userIdが自動で登録され、登録完了メッセージが返信されます(手動でuserIdを調べる必要はありません)。

> **本番切り替え時の注意**: 動作確認期間中は`LINE_USER_ID_YUKI`と`LINE_USER_ID_MITSUKI`が一志さん本人のuserIdに
> 仮設定されていました。ゆうきさん・みつきさん本人の登録が完了したら、この2つのスクリプトプロパティの値は
> 上記の手順で自動的に本人のuserIdへ上書きされます。一志さん自身のuserIdは、現在`LINE_USER_ID_YUKI`または
> `LINE_USER_ID_MITSUKI`に入っている値を`LINE_USER_ID_KAZUSHI`にコピーして設定してください
> (一志さんご本人が改めて「一志」と送信して再登録しても構いません)。

### 2. スクリプトプロパティの設定

GASエディタ左メニュー「プロジェクトの設定」→「スクリプト プロパティ」で以下を追加してください。

**必須**

| キー | 内容 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Messaging APIのチャネルアクセストークン(長期) |
| `LINE_CHANNEL_SECRET` | LINEのChannel secret(今回は署名検証には使いませんが、将来の拡張用に保存しておくことを推奨) |
| `YAHOO_APP_ID` | Yahoo!デベロッパーネットワークで発行するアプリケーションID(YOLP用。無料。[登録ページ](https://e.developer.yahoo.co.jp/register)から取得) |
| `LINE_WEBHOOK_TOKEN` | Webhook用の簡易トークン(任意の英数字文字列を自分で決めて設定。手順3で使用) |

**配信先(本番切り替え用。値を設定するだけで配信対象に加わる。未設定の間は空欄のままでよい)**

| キー | 内容 |
|---|---|
| `LINE_USER_ID_KAZUSHI` | 一志さんのuserId(ゆうきさん向け・みつきさん向け通知のCCを受信。計2通) |
| `LINE_USER_ID_KIKUMI` | きくみさんのuserId(一志さんと同様、ゆうきさん向け・みつきさん向け通知のCCを受信。計2通) |

**任意(未設定時はデフォルト値を使用。運用しながら調整可能)**

| キー | デフォルト | 内容 |
|---|---|---|
| `WEATHER_DRY_RUN` | `true` | `true`の間はLINE送信せずログ出力のみ(本番反映前はこのままにしてください)。確認ポイント③でOKが出たら`false`に変更。 |
| `YUKI_POP_THRESHOLD` | `50` | バス推奨とする降水確率(%)のしきい値。 |
| `YUKI_RAIN_INTENSITY_THRESHOLD_MMH` | `1` | バス推奨とする雨雲の降水強度しきい値(mm/h)。 |
| `MITSUKI_RAIN_BUFFER_MIN` | `10` | 雨天時に追加する移動バッファ(分)。 |
| `MITSUKI_DEFAULT_TRAVEL_MIN` | `15` | 自転車移動時間が取得できない場合のフォールバック値(分)。 |
| `MITSUKI_DEFAULT_SCHOOL_START` | `08:15` | カレンダーに時刻付きの予定が無い日の、通常登校の目安時刻(確定値)。 |
| `YUKI_DEFAULT_SCHOOL_END` | `16:00` | ゆうきさんの通常下校時刻。**仮値のため要確認**(下記「残っている論点」参照)。 |
| `MITSUKI_DEFAULT_SCHOOL_END` | `16:00` | みつきさんの通常下校時刻。**仮値のため要確認**(下記「残っている論点」参照)。 |
| `HOMEWARD_ALERT_LEAD_MIN` | `30` | 「下校時 雨雲通過予報」を下校予定時刻の何分前に送るか。 |

### 3. Webhookの公開設定(LINEの友だち登録を自動化するため)

1. GASエディタ右上「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択。
2. 「アクセスできるユーザー」を **「全員」** にしてください(「Google アカウントを持つ全員」ではLINEサーバーからのアクセスが拒否されます)。
3. デプロイ後に発行されるURLの末尾に `?webhook_token=(手順2で決めたLINE_WEBHOOK_TOKENの値)` を付与し、
   LINE Developersコンソールの「Messaging API設定」→「Webhook URL」に設定して「Webhookの利用」をONにしてください。
4. LINE公式アカウントマネージャーの「応答設定」で、Webhookからの応答を有効に、Bot自動応答メッセージ等は無効にしておくことを推奨します。

> **既知の制約**: GASのWebアプリはリクエストの生ヘッダーを読み取れないため、LINE公式の署名検証(X-Line-Signature)は実装していません。
> 代わりに上記のURLクエリトークン方式で簡易的なアクセス制御を行っています(既存の`doGet`側で使われている`WEBAPP_TOKEN`方式と同じ考え方です)。

> **動作確認について**: `?webhook_token=...`付きのURLをブラウザで直接開いてもWebhookの動作確認にはなりません
> (ブラウザでのアクセスはGET、LINEからの実際の呼び出しはPOSTで、GASでは別の関数(`doGet`/`doPost`)が処理するためです)。
> ブラウザでGETアクセスした場合は診断用の案内メッセージが表示されるだけです。実際の疎通確認は、
> LINE Developersコンソールの「Webhook URLを検証」ボタン、または友だち追加後に実際にメッセージを送ってみることで行ってください。

### 4. トリガーの設定(最初に1回だけ手動実行)

GASエディタで `setupWeatherTriggers` 関数を選択して実行してください。実行時に権限の許可を求められます。
これで「前日21:00頃」「当日6:30頃」の2つの時刻トリガーが設定されます
(GASの`nearMinute`仕様上、実際の実行時刻は指定時刻の前後15分程度ずれることがあります)。

既存の `setupTrigger()`(15分おきのファイル監視)とは別トリガーなので、干渉しません。

## テスト方法(確認ポイント②)

`WEATHER_DRY_RUN` はデフォルト `true` なので、以下のテストではLINEに実際のメッセージは送信されません(ログに出力されるだけです)。

1. **ロジック単体テスト(気象API・カレンダー不要ですぐ実行可)**
   GASエディタで `testYukiLogicCases` / `testMitsukiLogicCases` / `testMitsukiEscortLogicCases` を実行し、
   実行ログでしきい値の境界(50%ちょうど等)や、朝良好・帰り雨天時に「往復バス」に切り替わる文面(修正1)が
   意図通りに動くか確認してください。
2. **外部API疎通確認**(要`YAHOO_APP_ID`設定)
   `testWeatherApiSmoke` を実行し、地点のジオコーディング結果・降水確率・降水ナウキャスト・自転車移動時間が
   それぞれ妥当な値で取得できているかログで確認してください。
   `testHomewardDepartureSmoke` を実行すると、実際のカレンダーを使って明日の下校予定時刻が
   意図通りに算出されるか(部活等の予定があればその終了時刻、無ければデフォルト時刻)を確認できます。
   `testDangerWarningSmoke` を実行すると、気象庁の警報・注意報JSONの生データ(対象3市町村の照合結果、
   および全市町村の先頭30件)がログに出ます。この結果を教えていただければ、危険警報の判定ロジックを確定します。
3. **本番相当の一連の流れ**
   `testFullRunDryRun` を実行し、実際のカレンダー予定・実際の天気予報を使って
   `sendProvisionalNotification` / `sendFinalNotification` を1回ずつ動かします。
   ログに出力されるメッセージ文面を見て、内容が妥当か確認してください。
   `sendFinalNotification`側(確定版)を実行すると、下校時雨雲アラート用の使い捨てトリガーも実際に予約されます
   (下校予定時刻の30分前に発火するまでは送信されません。すぐに内容だけ確認したい場合は
   `testHomewardDepartureSmoke`で算出結果を先に見ておくと予定時刻の見当がつきます)。

問題なければ `WEATHER_DRY_RUN` を `false` に変更し、実際に自分(または少人数)宛にテスト送信してから、
最終的な本番反映(確認ポイント③)に進んでください。

## 設計上のポイント・既知の制約

- **降水確率のデータソース**: 気象庁の天気予報JSON(`https://www.jma.go.jp/bosai/forecast/data/forecast/230000.json`、愛知県)から、
  豊田市・刈谷市を含む「西部」区分の6時間区分ごとの降水確率を使用しています。認証不要・無料です。
- **降水ナウキャストのデータソース**: Yahoo! YOLP気象情報API(気象庁 高解像度降水ナウキャスト由来)を使用しています。
  ただし**YOLPの予測は直近1時間程度先までが上限**のため、仕様書の「今後1〜2時間以内」を厳密には満たせません。
  この制約により、ナウキャストによるバス推奨判定は、実質的に意味のある「当日6:30の確定版」でのみ行い、
  10時間以上先を予測する「前日21:00の暫定版」では降水確率のみで判定する設計にしています。
- **地点の緯度経度**: 住所文字列をGASのジオコーディング機能で実行時に変換し、スクリプトプロパティに永続キャッシュしています
  (`GEO_CACHE_*`というキーで自動保存されます。住所を変更した場合は該当のプロパティを削除して再取得させてください)。
- **みつきさんの移動時間**: みつきさんは自転車通学のため、GASのMapsサービス(自転車ルート)で自宅→目的地の
  所要時間を都度取得しています。取得に失敗した場合は`MITSUKI_DEFAULT_TRAVEL_MIN`(初期値15分)にフォールバックします。
- **配信先**: ゆうきさん向け通知(登校天気予報・下校時アラート)は「ゆうきさん本人 + 一志さん(CC) + きくみさん(CC)」、
  みつきさん向け通知(出発時刻・送迎提案・下校時アラート)は「みつきさん本人 + 一志さん(CC) + きくみさん(CC)」へ、
  それぞれ同一内容を送信します。userIdが未設定の宛先には送信されずログにスキップ理由が出るだけなので、
  `LINE_USER_ID_KAZUSHI` / `LINE_USER_ID_KIKUMI`を設定するだけで、コード変更なしに配信対象へ加わります。
- **下校時刻の算出**(`getHomewardDepartureTime_`、`WeatherNotify_Config.gs`): ゆうき・みつき共通のロジックです。
  対象日に時刻付きの実予定(部活動等、学校発の予定)があれば、最も遅く終わる予定の終了時刻を使います。
  登校日であれば、通常下校時刻(`YUKI_DEFAULT_SCHOOL_END` / `MITSUKI_DEFAULT_SCHOOL_END`)も候補に入れ、
  両方候補がある場合はより遅い方(＝より現実的な時刻)を採用します。登校日でもなく予定も無い日は対象外です。
  みつきさんの呼び出しでは、5番目の引数(`excludeLabelKeywords`)に`MITSUKI_LESSON_NAMES_`(英語・お茶)を渡し、
  これらの予定を候補から除外しています。英語・お茶はいったん帰宅してから家庭発で出発する予定であり、
  「学校から家に向かう時刻」ではないためです(含めてしまうと、実際の下校時刻より大幅に遅い時刻が
  下校予定として算出され、下校時雨雲アラートの発火予約が大きくずれるバグになります。過去に発生した実例です)。
- **下校時 雨雲通過予報の予約の仕組み**: 確定版配信(`sendFinalNotification`)のタイミングで、下校予定時刻の
  `HOMEWARD_ALERT_LEAD_MIN`分前(初期値30分)に発火する使い捨てトリガーを`ScriptApp.newTrigger(...).at(...)`で作成します。
  既存の`家族スケジュール自動登録.gs`の`scheduleNotification_`と同じ、スクリプトプロパティ+使い捨てトリガーによる
  予約パターンを踏襲しています。発火時にその場でナウキャストを取得するため、直近1時間程度までしか予測できない
  YOLPの制約があっても、実用上意味のあるタイミングで情報を届けられます。
- **出典リンク**: 降水確率(気象庁)・雨雲通過予報(YOLP)のうち、そのメッセージの判定で実際に使ったデータ種別に
  応じてリンクを出し分けています(`buildSourceLinksLine_`)。

## 残っている論点(運用しながらの調整、または要確認)

- **`YUKI_DEFAULT_SCHOOL_END` / `MITSUKI_DEFAULT_SCHOOL_END`(初期値16:00)は実際の下校時刻に合わせた仮値です。**
  実態に合わせてスクリプトプロパティで調整してください(`MITSUKI_DEFAULT_SCHOOL_START`と同様の位置づけです)。
- `HOMEWARD_ALERT_LEAD_MIN`(下校時アラートを送るタイミング、初期値30分前)も仮の値です。運用しながら調整してください。
- 登校日判定(`NON_SCHOOL_DAY_KEYWORDS_`)は、カレンダー上の「【ゆうき】」「【みつき】」タグ付き終日予定に
  「夏休み」等のキーワードが含まれているかで判定しています。学校からの書類の記載表現が異なる場合は、
  `WeatherNotify_Config.gs`のキーワード一覧を実態に合わせて調整してください。
- しきい値(`YUKI_POP_THRESHOLD`等)はすべてスクリプトプロパティで運用しながら調整可能です。
- ゆうきさんの登校判定(朝の登校可否)は「土日は必ず登校日ではない」という前提のため、模試等で土曜に登校する日が
  あっても、朝の登校天気予報は現状通知されません(下校時刻算出・下校時アラートは、時刻付きの予定さえあれば
  土日でも対象になります。みつきさんの各機能も同様に、時刻付きの予定があれば土日でも通知されます)。
  実際にそのようなケースが発生する場合はご相談ください。
- みつきさんの送迎提案(項目4)は、カレンダーの予定タイトルに「部」または「お茶」という文字列が含まれるかで
  対象日を判定しています(「英語」は対象外)。表記が変わった場合は`WeatherNotify_MitsukiLogic.gs`の
  `isMitsukiActivityRelevant_`を調整してください。
