# family-automation

家族の予定を自動でGoogleカレンダーに集約するGoogle Apps Script(GAS)プロジェクト一式です。
`gas/` フォルダの中身を、そのままGoogle Apps Scriptエディタにコピーして使います
(clasp等でのデプロイは前提にしていません。ファイル単位でコピー&ペーストしてください)。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `家族スケジュール自動登録.gs` | 既存資産。「家族スケジュール」フォルダのPDF/写真をGemini APIで解析し、Googleカレンダーへ自動登録する。 |
| `appsscript.json` | GASのマニフェスト。タイムゾーン(Asia/Tokyo)、Webアプリの公開設定、Calendar詳細サービスの有効化を含む。 |
| `WeatherNotify_Config.gs` | 今回追加した天気×カレンダー通知機能の設定値(地点住所・しきい値・登校日判定の共通ロジック)。 |
| `WeatherNotify_Api.gs` | 気象庁 予報JSON(降水確率)・Yahoo! YOLP気象情報API(降水ナウキャスト)・ジオコーディング・自転車移動時間の取得。 |
| `WeatherNotify_YukiLogic.gs` | ゆうきさん(刈谷高校)のバス/自転車判定ロジック。 |
| `WeatherNotify_MitsukiLogic.gs` | みつきさん(前林中学校)の出発時刻リマインドロジック。 |
| `WeatherNotify_Line.gs` | LINE Messaging APIへのpush送信、および友だち追加後のuserId自動登録用Webhook(`doPost`)。 |
| `WeatherNotify_Main.gs` | 配信のメインエントリ(`sendProvisionalNotification` / `sendFinalNotification`)とトリガー設定。 |
| `WeatherNotify_Test.gs` | 本番反映前の動作確認用テスト関数群。 |

## セットアップ手順(天気×カレンダー通知機能)

### 0. 前提: 既存機能のスクリプトプロパティ

既存の `家族スケジュール自動登録.gs` 側で、すでに以下が設定済みであることを前提にしています。

- `GEMINI_API_KEY` / `FOLDER_ID` / `CALENDAR_ID`

`CALENDAR_ID`(家族の予定が登録されている共有カレンダー)を、今回の天気×カレンダー通知機能でもそのまま再利用します
(みつきさんの「【みつき】」タグ付き予定の検索、登校日判定などに使用)。

### 1. LINE公式アカウントを友だち追加してもらう(最初のステップ)

ゆうきさん・みつきさん・きくみさんに、設定済みのLINE公式アカウントをQRコード等で友だち追加してもらってください
(一志さんはこれまでの動作確認で既に友だち追加・登録済みです)。
友だち追加が完了し、後述のWebhookを設定した状態で、それぞれ本人のLINEアプリから公式アカウントのトーク画面で

- ゆうきさん → `ゆうき` と送信
- みつきさん → `みつき` と送信
- きくみさん → `きくみ` と送信

してもらうと、対応するスクリプトプロパティ(`LINE_USER_ID_YUKI` / `LINE_USER_ID_MITSUKI` / `LINE_USER_ID_KIKUMI`)に
userIdが自動で登録され、登録完了メッセージが返信されます(手動でuserIdを調べる必要はありません)。

> **本番切り替え時の注意**: 動作確認期間中は`LINE_USER_ID_YUKI`と`LINE_USER_ID_MITSUKI`が一志さん本人のuserIdに
> 仮設定されていました。ゆうきさん・みつきさん本人の登録が完了したら、この2つのスクリプトプロパティの値は
> 上記の手順で自動的に本人のuserIdへ上書きされます。一志さん自身のuserIdは、現在`LINE_USER_ID_YUKI`または
> `LINE_USER_ID_MITSUKI`に入っている値を`LINE_USER_ID_KAZUSHI`にコピーして設定してください
> (一志さんご本人が改めて「一志」と送信して再登録しても構いません)。

### 2. スクリプトプロパティの設定

GASエディタ左メニュー「プロジェクトの設定」→「スクリプト プロパティ」で以下を追加してください。

**必須**

| キー | 内容 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Messaging APIのチャネルアクセストークン(長期) |
| `LINE_CHANNEL_SECRET` | LINEのChannel secret(今回は署名検証には使いませんが、将来の拡張用に保存しておくことを推奨) |
| `YAHOO_APP_ID` | Yahoo!デベロッパーネットワークで発行するアプリケーションID(YOLP用。無料。[登録ページ](https://e.developer.yahoo.co.jp/register)から取得) |
| `LINE_WEBHOOK_TOKEN` | Webhook用の簡易トークン(任意の英数字文字列を自分で決めて設定。手順3で使用) |

**配信先(本番切り替え用。値を設定するだけで配信対象に加わる。未設定の間は空欄のままでよい)**

| キー | 内容 |
|---|---|
| `LINE_USER_ID_KAZUSHI` | 一志さんのuserId(ゆうきさん向け・みつきさん向け通知のCCを受信。計2通) |
| `LINE_USER_ID_KIKUMI` | きくみさんのuserId(一志さんと同様、ゆうきさん向け・みつきさん向け通知のCCを受信。計2通) |

**任意(未設定時はデフォルト値を使用。運用しながら調整可能)**

| キー | デフォルト | 内容 |
|---|---|---|
| `WEATHER_DRY_RUN` | `true` | `true`の間はLINE送信せずログ出力のみ(本番反映前はこのままにしてください)。確認ポイント③でOKが出たら`false`に変更。 |
| `YUKI_POP_THRESHOLD` | `50` | バス推奨とする降水確率(%)のしきい値。 |
| `YUKI_RAIN_INTENSITY_THRESHOLD_MMH` | `1` | バス推奨とする雨雲の降水強度しきい値(mm/h)。 |
| `MITSUKI_RAIN_BUFFER_MIN` | `10` | 雨天時に追加する移動バッファ(分)。 |
| `MITSUKI_DEFAULT_TRAVEL_MIN` | `15` | 自転車移動時間が取得できない場合のフォールバック値(分)。 |
| `MITSUKI_DEFAULT_SCHOOL_START` | `08:15` | カレンダーに時刻付きの予定が無い日の、通常登校の目安時刻(確定値)。 |

### 3. Webhookの公開設定(LINEの友だち登録を自動化するため)

1. GASエディタ右上「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択。
2. 「アクセスできるユーザー」を **「全員」** にしてください(「Google アカウントを持つ全員」ではLINEサーバーからのアクセスが拒否されます)。
3. デプロイ後に発行されるURLの末尾に `?webhook_token=(手順2で決めたLINE_WEBHOOK_TOKENの値)` を付与し、
   LINE Developersコンソールの「Messaging API設定」→「Webhook URL」に設定して「Webhookの利用」をONにしてください。
4. LINE公式アカウントマネージャーの「応答設定」で、Webhookからの応答を有効に、Bot自動応答メッセージ等は無効にしておくことを推奨します。

> **既知の制約**: GASのWebアプリはリクエストの生ヘッダーを読み取れないため、LINE公式の署名検証(X-Line-Signature)は実装していません。
> 代わりに上記のURLクエリトークン方式で簡易的なアクセス制御を行っています(既存の`doGet`側で使われている`WEBAPP_TOKEN`方式と同じ考え方です)。

> **動作確認について**: `?webhook_token=...`付きのURLをブラウザで直接開いてもWebhookの動作確認にはなりません
> (ブラウザでのアクセスはGET、LINEからの実際の呼び出しはPOSTで、GASでは別の関数(`doGet`/`doPost`)が処理するためです)。
> ブラウザでGETアクセスした場合は診断用の案内メッセージが表示されるだけです。実際の疎通確認は、
> LINE Developersコンソールの「Webhook URLを検証」ボタン、または友だち追加後に実際にメッセージを送ってみることで行ってください。

### 4. トリガーの設定(最初に1回だけ手動実行)

GASエディタで `setupWeatherTriggers` 関数を選択して実行してください。実行時に権限の許可を求められます。
これで「前日21:00頃」「当日6:30頃」の2つの時刻トリガーが設定されます
(GASの`nearMinute`仕様上、実際の実行時刻は指定時刻の前後15分程度ずれることがあります)。

既存の `setupTrigger()`(15分おきのファイル監視)とは別トリガーなので、干渉しません。

## テスト方法(確認ポイント②)

`WEATHER_DRY_RUN` はデフォルト `true` なので、以下のテストではLINEに実際のメッセージは送信されません(ログに出力されるだけです)。

1. **ロジック単体テスト(気象API・カレンダー不要ですぐ実行可)**
   GASエディタで `testYukiLogicCases` / `testMitsukiLogicCases` を実行し、実行ログでしきい値の境界(50%ちょうど等)が
   意図通りに動くか確認してください。
2. **外部API疎通確認**(要`YAHOO_APP_ID`設定)
   `testWeatherApiSmoke` を実行し、地点のジオコーディング結果・降水確率・降水ナウキャスト・自転車移動時間が
   それぞれ妥当な値で取得できているかログで確認してください。
3. **本番相当の一連の流れ**
   `testFullRunDryRun` を実行し、実際のカレンダー予定・実際の天気予報を使って
   `sendProvisionalNotification` / `sendFinalNotification` を1回ずつ動かします。
   ログに出力されるメッセージ文面を見て、内容が妥当か確認してください。

問題なければ `WEATHER_DRY_RUN` を `false` に変更し、実際に自分(または少人数)宛にテスト送信してから、
最終的な本番反映(確認ポイント③)に進んでください。

## 設計上のポイント・既知の制約

- **降水確率のデータソース**: 気象庁の天気予報JSON(`https://www.jma.go.jp/bosai/forecast/data/forecast/230000.json`、愛知県)から、
  豊田市・刈谷市を含む「西部」区分の6時間区分ごとの降水確率を使用しています。認証不要・無料です。
- **降水ナウキャストのデータソース**: Yahoo! YOLP気象情報API(気象庁 高解像度降水ナウキャスト由来)を使用しています。
  ただし**YOLPの予測は直近1時間程度先までが上限**のため、仕様書の「今後1〜2時間以内」を厳密には満たせません。
  この制約により、ナウキャストによるバス推奨判定は、実質的に意味のある「当日6:30の確定版」でのみ行い、
  10時間以上先を予測する「前日21:00の暫定版」では降水確率のみで判定する設計にしています。
- **地点の緯度経度**: 住所文字列をGASのジオコーディング機能で実行時に変換し、スクリプトプロパティに永続キャッシュしています
  (`GEO_CACHE_*`というキーで自動保存されます。住所を変更した場合は該当のプロパティを削除して再取得させてください)。
- **みつきさんの移動時間**: みつきさんは自転車通学のため、GASのMapsサービス(自転車ルート)で自宅→目的地の
  所要時間を都度取得しています。取得に失敗した場合は`MITSUKI_DEFAULT_TRAVEL_MIN`(初期値15分)にフォールバックします。
- **配信先**: ゆうきさん向け通知は「ゆうきさん本人 + 一志さん(CC) + きくみさん(CC)」の3名、みつきさん向け通知は
  「みつきさん本人 + 一志さん(CC) + きくみさん(CC)」の3名へ、それぞれ同一内容を送信します
  (一志さん・きくみさんは1日あたり最大2通、ゆうきさん向け・みつきさん向けの両方を受信します)。
  userIdが未設定の宛先には送信されずログにスキップ理由が出るだけなので、`LINE_USER_ID_KAZUSHI` /
  `LINE_USER_ID_KIKUMI`を設定するだけで、コード変更なしに配信対象へ加わります。

## 残っている論点(運用しながらの調整、または要確認)

- 登校日判定(`NON_SCHOOL_DAY_KEYWORDS_`)は、カレンダー上の「【ゆうき】」「【みつき】」タグ付き終日予定に
  「夏休み」等のキーワードが含まれているかで判定しています。学校からの書類の記載表現が異なる場合は、
  `WeatherNotify_Config.gs`のキーワード一覧を実態に合わせて調整してください。
- しきい値(`YUKI_POP_THRESHOLD`等)はすべてスクリプトプロパティで運用しながら調整可能です。
- ゆうきさんの登校判定は「土日は必ず登校日ではない」という前提のため、模試等で土曜に登校する日があっても
  現状は通知されません(みつきさんは時刻付きの予定があれば土日でも通知されるため、この制約はゆうきさん側のみ)。
  実際にそのようなケースが発生する場合はご相談ください。
